# Principes

La clarté ici est **transversale** : elle s'applique une fois le type Diátaxis choisi.
Pour classer et calibrer le contenu → [diataxis.md](diataxis.md).

## Clarté littéraire

- Phrases courtes. Une proposition principale par phrase quand c'est possible.
- Mots concrets avant les abstractions.
- Sujet-verbe-complément en tête ; digressions après, ou coupées.
- Voix active par défaut (`On lance X` plutôt que `X peut être lancé`).

## Charge mentale

La lecture coûte de l'attention. Chaque digression, jargon non défini, ou double négation augmente le coût.

- Définir un terme technique **la première fois**, puis le réutiliser.
- Séparer *quoi* / *pourquoi* / *comment* (pas les trois dans le même paragraphe).
- Mettre les prérequis avant l'action.
- Couper ce qui n'aide pas à agir ou à décider.

## Attention span en baisse

Les lecteurs scannent d'abord, lisent ensuite — s'ils en ont besoin.

- Les 5 premières lignes doivent répondre : *c'est quoi* + *pour qui* + *prochaine action*.
- Signaux visuels (titres, gras, listes, emoji de section) pour permettre le **saut** vers la bonne zone.
- Une section = un job. Si deux jobs, deux sections.

## Tweaks visuels qui accélèrent

| Signal | Quand |
|---|---|
| Titre H2/H3 | Changer de job / d'étape |
| **Gras** | Mot ou expression à trouver en scroll rapide |
| *Italique* | Nuance, exception, « optionnel » |
| `code` | Commande, chemin, clé config, nom exact |
| Liste | Étapes, options, inventaire |
| Tableau | Comparaison (A vs B), mapping |
| Callout / citation | Avertissement unique (⚠️ une fois, pas partout) |
| Emoji en tête de titre | Ancre de scan (`🛠 Install`, `🧪 Tests`) — max ~1 par section |

## Emojis : critère unique

Utiliser un emoji **seulement si** ça accélère la recherche d'information (repère de section, statut, type d'action).

Sinon : l'enlever.
