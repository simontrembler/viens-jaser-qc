# Checklist docs-claires

## Diátaxis

- [ ] Type dominant nommé (tutorial / how-to / référence / explication)
- [ ] Boussole cohérente (action↔cognition × étude↔travail)
- [ ] Pas de mélange non signalé ; digressions hors-type → liens
- [ ] Titre aligné sur le type (*How to…*, *About…*, nom de symbole, leçon…)

## Clarté / scan

- [ ] Les 5 premières lignes répondent au besoin du **type** (pas un fourre-tout)
- [ ] Une section = un job
- [ ] Titres scannables
- [ ] Paragraphes courts ; listes pour les étapes (tutorial / how-to)
- [ ] **Gras** réservé aux ancres
- [ ] `code` pour commandes, chemins, IDs seulement
- [ ] Emojis seulement s'ils accélèrent le scan / le statut
- [ ] Aucune commande, URL ou version inventée
- [ ] Termes techniques définis à la première occurrence (sauf référence pure déjà contextuelle)
- [ ] Prérequis avant les actions (tutorial / how-to)
